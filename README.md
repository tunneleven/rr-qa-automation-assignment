# RR QA Automation Assignment

Automated UI and browser-network testing for [TMDB Discover](https://tmdb-discover.surge.sh/), implemented with Python, pytest, and Playwright.

> **Current status:** The assignment deliverables are complete: documented test design, automated UI and browser-network coverage, execution results, defect evidence, and a CI workflow. Confirmed defects remain strict expected failures until fixed.

## Project structure

```text
.
├── pages/
│   ├── discover_page.py   # Page object: locators and reusable user actions
│   └── endpoints.py       # Application routes and TMDB endpoints used everywhere
├── tests/
│   ├── ui/                # User-visible functional and negative tests
│   ├── api/               # Browser request/response assertions
│   ├── assertions.py      # Assertion helpers shared by the UI and API suites
│   ├── known_defects.py   # Exception used only for confirmed defect signatures

├── test_data/             # Stable input data when parametrization alone is insufficient
├── utils/                 # Small cross-cutting helpers (structured action logging)
├── docs/
│   ├── test-strategy.md
│   ├── test-cases.md
│   ├── coverage-matrix.md
│   ├── defects.md
│   └── test-results.md
├── evidence/              # Committed defect screenshots and redacted network notes
├── artifacts/             # Committed HTML report; generated JUnit and console reports
├── test-results/          # Generated Playwright traces and screenshots (ignored)
├── pyproject.toml         # Dependencies and pytest/Ruff configuration
└── uv.lock                # Reproducible dependency lock (generated by `uv sync`)
```

## Setup

Prerequisites: Python 3.11+ and [uv](https://docs.astral.sh/uv/).

```bash
uv sync --locked

# Linux: install Chromium and its required system libraries
uv run playwright install --with-deps chromium

# macOS or Windows: install the browser without Linux system packages instead
uv run playwright install chromium

uv run pre-commit install
```

Use the browser-install command for your operating system, not both. The last command installs the repository's quality checks as a local Git pre-commit hook.

## Test commands

```bash
# Entire suite; console logging and HTML report are enabled by default
# Uses the full Chromium binary in headless mode (configured in pyproject.toml)
uv run pytest

# Critical checks only
uv run pytest -m smoke

# Visible browser for local debugging
uv run pytest --headed --tracing=on

# Static quality checks
uv run ruff check .
uv run ruff format --check .

# Run the same checks used before every commit
uv run pre-commit run --all-files
```

The self-contained report is generated at `artifacts/report.html` and committed as reviewable execution evidence. Playwright failure screenshots and retained traces are generated under `test-results/` unless `--output` overrides that location. JUnit, console, trace, and screenshot outputs remain ignored locally; CI publishes them as a downloadable artifact.

## CI approach

The [`CI` workflow](.github/workflows/ci.yml) runs for pull requests and pushes to `main`, on manual dispatch, and on a weekly schedule. Concurrency cancels obsolete runs from the same ref.

1. **Quality checks** install Python 3.12 and the locked dependencies with uv, then run every pre-commit check.
2. **Chromium regression** starts only after quality checks pass. It installs full Chromium with its Linux dependencies and executes the complete pytest suite against the live demo.

The workflow uses the same full Chromium channel as local execution. Because the target and its TMDB data are external, failures are not retried automatically: availability, setup, and assertion failures remain visible for investigation. Confirmed product defects are XFAIL only when a dedicated exception identifies their documented signature. Any unrelated failure remains an ordinary failure, and an unexpectedly fixed defect becomes a strict XPASS failure until its test and defect record are reviewed.

Pytest writes a console report, self-contained HTML report, and JUnit XML. The workflow also retains Playwright traces and screenshots on failure, adds the console result to the job summary, and uploads the generated evidence for 30 days even when regression assertions fail. The current recorded baseline is 30 passed tests and 11 strict expected failures; see [`docs/test-results.md`](docs/test-results.md) for the detailed assessment.

## Design decisions

- The official Playwright pytest plugin supplies an isolated browser context and page per test.
- The pytest defaults select the full `chromium` channel so headless and headed runs use the same Chromium network implementation; Playwright's separate headless-shell binary is not used.
- Playwright locators and web-first assertions will be used instead of fixed sleeps.
- Page objects centralize selectors and reusable actions; assertions remain in tests.
- Application routes and API endpoints live in one module shared by page objects and parametrized cases.
- Repeated request, rendering, and query-parameter checks live in shared assertion helpers.
- Pytest fixtures provide focused setup, markers organize execution, and parametrization removes duplication.
- UI behavior and the browser requests that support it are asserted together where that provides stronger evidence.
- Traces and screenshots are retained on failure; console logs and a self-contained HTML report are enabled by default.
- Confirmed known defects use strict expected failures only when a dedicated exception matches the documented defect signature; unrelated failures cannot be classified as XFAIL.
- Ruff provides one fast linter, import sorter, and formatter; pre-commit also checks syntax, configuration files, whitespace, merge markers, debug statements, secrets, and oversized files.

See [the test strategy](docs/test-strategy.md) for scope, techniques, risks, and exit criteria.
